# actdbg — Аудит: чего не хватает

> Комплексный аудит по 3 осям (adoption, product, tech) с единым приоритизированным backlog'ом.  
> Стадия проекта: pet с амбицией open-source traction.

---

## TL;DR

actdbg закрывает реальную боль (shell при падении с env reconstruction) лучше, чем любой альтернативный инструмент — это конкурентное преимущество не оспаривается. Главная проблема не в фичах, а в **невидимости**: нет Homebrew, нет binary releases, нет GitHub Topics — 70% потенциальных пользователей не смогут даже установить его «в один клик». Второй по силе gap — **убитый killer feature**: `rerun --from N` останавливается на первом `uses:`-шаге жёстким `return nil`, а реальные workflow состоят из uses: в 90%+ случаев. Без этого фикса «rerun» работает только в демо-условиях. Техкачество достаточно для pet-стадии, но есть один системный риск: отсутствие обработки Ctrl+C ведёт к накоплению GB образов `actdbg/snap:*` — первый же active user получит «disk is full». Приоритет: сначала дистрибуция (Homebrew + binary), потом `rerun` skip uses:, потом сигналы.

## SWOT

### Strengths (есть и работает)
- **Shell с env reconstruction** — единственный инструмент в нише, восстанавливает $GITHUB_ENV + snapshot-дельты. Даёт именно то, чего просят в act#2090 с 2023 года.
- **Честность** — `actdbg check` флагирует расхождения с GitHub; tool не притворяется заменой CI
- **Time-travel (back/diff/rerun)** — уникальная фича; ни у кого нет
- **TUI** — lazygit-style, command log (transparency)
- **Replay** — по URL GitHub run; полезна при сложных воспроизведениях
- **Документация** — README честный, информативный, хорошо написан

### Weaknesses (сломано или отсутствует)
- **Дистрибуция** — только `go install`, нет Homebrew, нет binary releases
- **`rerun` для uses:-шагов** — жёсткий `return nil`, не skip; сломан killer feature
- **Нет GitHub Topics** — невидим в GitHub Search
- **Нет Ctrl+C cleanup** — накопление контейнеров/образов; системный риск
- **Нет CHANGELOG/Releases** — выглядит неживым для внешних
- **TUI experimental** — layout quirks, нет скриншота в README
- **Тестовое покрытие** — enginerun, replay, ui — ≤1/5; snapshot — 2/5

### Opportunities (что может дать traction)
- act#2090 открыт с 2023, 70k★ у act — аудитория существует и ищет решение
- CircleCI "rerun with SSH" — самая любимая фича CI; GitHub ничего подобного не предлагает
- action-tmate имеет реальные UX-проблемы (UX nightmare + security); замена есть
- HN/Reddit — сообщество активно обсуждает дебаг GitHub Actions, канал для launch существует

### Threats (риски)
- GitHub может добавить нативный SSH-debug в Actions (пока не планирует)
- nektos/act может наконец закрыть issue #2090 своими силами
- Малая известность → первый пользователь не найдёт

## Белые пятна (что можно было бы закрыть)

1. **Skip uses: в rerun** — не полный rerun uses:, а skip с варнингом + продолжить run:-шаги. Решает 90% реальных сценариев.
2. **Multi-job debugging** — сейчас только first failure. При параллельных jobs пользователь не видит картину целиком.
3. **Breakpoint в шаге** — пауза ПЕРЕД падением (не после). Нужно модифицировать workflow YAML автоматически или внедрить hook.
4. **${{ }} preview** — показать как будет вычислен ${{ github.sha }} до выполнения, не после.
5. **actdbg init** — автоматический scaffold `.actrc`, `.secrets.example`, tips для первого запуска. Снизит трение onboarding'а.

## Топ-3 действия прямо сейчас

### 1. 30 секунд: GitHub Topics
**Действие:** Settings → репо → Topics → добавить: `github-actions debugging ci golang cli tui`  
**Почему:** Единственное, что не стоит времени, но напрямую влияет на discoverability в GitHub Search.

### 2. 2 часа: Ctrl+C cleanup
**Действие:** В `main.go` добавить `signal.NotifyContext` + `defer enginerun.Clean(ctx)` при прерывании.  
**Почему:** Это тихая бомба. Каждый активный пользователь накопит GB образов `actdbg/snap:*`. Первый же issue будет "disk is full". Лучше закрыть до того, как кто-то встретит.

### 3. 2-4 часа: GoReleaser + Homebrew tap
**Действие:**
```bash
brew install goreleaser
goreleaser init          # генерирует .goreleaser.yml
# Создать repo: Socialpranker/homebrew-actdbg
# Добавить brews: секцию в .goreleaser.yml
# Добавить gh Actions job: goreleaser release
```
**Почему:** Это единственное что разблокирует 70% macOS-пользователей. `brew install actdbg` vs `go install github.com/Socialpranker/actdbg@latest` — разница в 10x по трению для первой установки.

## Counter-arguments (steel-man)

### CA1: "action-tmate даёт SSH в реальный GitHub — зачем локальный debugger?"
**Кто говорит:** Реальные пользователи, выбравшие tmate. [S05]  
**Аргумент:** tmate даёт отладку в настоящей среде GitHub (те же образы, те же secrets, реальный GITHUB_TOKEN).  
**Сила:** средняя (3/5)  
**Наш ответ:** tmate = постфактум-отладка после push; actdbg = pre-push итерация за секунды без трат GitHub Minutes. Они решают разные моменты цикла. Самый сильный use case actdbg — быстрые iteration loops (20+ попыток); для одной сложной отладки со secrets — tmate.  
**Что меняет в выводах:** ничего, но важно чётко сформулировать positioning — не «замена tmate», а «дополнение для другого момента».

### CA2: "Локальное != GitHub — зачем инвестировать в локальную отладку?"
**Кто говорит:** Статьи про CI/CD best practices. [S05]  
**Аргумент:** Среда act отличается от GitHub: другие образы, нет OIDC, нет реальных secrets, нет кешей. Часть проблем воспроизводится только на GitHub.  
**Сила:** высокая (4/5) — это самый честный контраргумент  
**Наш ответ:** act использует те же Docker образы Ubuntu; по данным сообщества ~80-90% проблем воспроизводится локально. actdbg честно говорит об ограничениях через `check`. ROI: сэкономить 90% циклов отладки локально, оставшиеся 10% решать через tmate/ACTIONS_STEP_DEBUG.  
**Что меняет в выводах:** Подчёркивает важность `actdbg check` как дифференциатора — это не баг инструмента, а продуманная честность.

### CA3: "rerun не работает (uses:) — значит core value proposition сломана"
**Кто говорит:** Hypothetical early adopter, встретивший баг.  
**Аргумент:** Если я не могу перезапустить workflow с шага, где починил код — зачем actdbg вообще? `actdbg shell` работает, но rerun — это главная фича.  
**Сила:** высокая (4/5)  
**Наш ответ:** Правда. Это приоритет #5 в NOW-backlog. Фикс — skip uses: с продолжением run:-шагов — занимает 2-3 часа и закрывает 90% реальных сценариев. Shell остаётся полностью рабочим.  
**Что меняет в выводах:** rerun fix должен быть в NOW, не NEXT.
